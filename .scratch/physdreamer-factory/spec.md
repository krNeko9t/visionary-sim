本轮是可运行交付：每个新入口真实加载、出画面、抓取、松手的 GPU smoke；记录固定层静止、材料计数与当前 Intel UHD Graphics 770 性能。60 fps / 零丢时仍是原目标，未达到如实记录但不阻止实现交付。不重跑旧 08 全矩阵，不进行无界 r 穷举、薄结构或求解器重设计。

## 最小工厂 interface

- 一个共享运行时 module 负责加载、清洗、动态/固定切分、材料标签延拓、SoftBody/scenery 组装、边界与诊断。场景仅声明名称、资产根、米制 r、elementSize、材料/抓取参数和是否要求固定材料；不得复制三份算法。保留一次共享准备 promise、失败可诊断、资源清理与前景物理范围/完整观察范围分离。
- 一个共享离线准备 module 和一个共享校准 module；推荐正式入口 `prepare-physdreamer.js --scene NAME` 与 `calibrate-physdreamer.js --scene NAME`。旧 prepare/calibrate-alocasia 命令作为薄兼容入口，旧显式参数及输出位置仍可用；不能保留第二份算法。运行时不依赖 tools 或 Node。
- 资产仍为 foreground.ply、moving_part_points.ply、background.ply、最后发布的 report.json。输入只读，输出按场景置于 ignored 的 public/splats/NAME；不能提交巨型原资产或派生产物。报告含场景、原始输入出处/哈希、变换、尺度声明、相机检查模式与逐帧数据、数量、包围盒。保留失败时失效旧报告与原输入保护。
- 新场景尺度暂声明 clean 转正后高度 0.30 m，明确是用于模拟的人工物理尺度，不宣称数据集真实测量；共同变换仍为 scale*(x,z,-y)+translation，clean底部为0，水平居中。每场景记录计算出的比例与尺寸。前景距离仍先采用源单位0.01，并与 r 分开；真实切分检查后若需改变，记录依据。
- r 与 elementSize 独立；每场景通过少量真实候选及局部视图确定 r，记录固定/可动高斯和材料节点。若真实数据全动可声明允许无固定材料，运行时和校准工具一致处理；不能伪造静态规定来通过 alocasia 专用拒绝条件。空材料、无可动材料仍失败。当前调查三份 clean/moving 均非相同集合，尚不预判为全动。
- alocasia 已接受配置保持：r=.016 m、elementSize=.016 m、maxStretch=1.05、damping=2 /s、柔抓响应.003 s；旧相机检查55°及0.30 m尺度仍兼容。不要求重新校准或推翻其已接受证据限制。新场景可从这些交互数值起步，但必须自行记录为声明并完成真实 smoke，不宣称材料已标定。

## 相机 up 矫正

相机 JSON 均是 frames[].transform_matrix，4×4 c2w，局部+Y为图像up，原始资产声明世界+Z。所有矩阵已测为右手正交，最大正交误差小于4e-7。相机俯拍会增大 camera-up 与世界+Z夹角；它不是世界重力错误。

新工厂必须区分声明世界up与相机俯拍，保留原始逐帧夹角及矩阵合法性检查、记录最终阈值/判据/理由，不能只调大阈值来掩盖错误变换。由实施者在修正现有检查的定义与确有必要的新模式之间选择最小方案并写ADR；不要为一个合法强俯拍引入大配置面。旧alocasia命令的55°语义须兼容，或显式说明迁移且证明不改变已接受变换。此检查是位姿相容性而非测得重力。合成正立、俯拍、滚转、错误轴/倒置与无有效证据场景应能区分通过/拒绝的含义。

以下投影统计只是调查辅助：将声明世界up投影到图像平面再比较相机+Y，投影长度>=0.5的帧用于观察。它不是指定实施方案，也没有批准排除帧或阈值。若选择这种方案，必须解释证据不足时的行为，报告排除帧与原因，不能按超阈值剔除异常帧。
