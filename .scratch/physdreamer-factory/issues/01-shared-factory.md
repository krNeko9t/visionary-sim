# 01: 共享 PhysDreamer 工厂，保留 alocasia 可运行

**What to build:** 将当前已接受的 alocasia 经小配置接入共享运行时和离线准备/校准工厂，后续场景无需复制算法；用户仍能用原命令准备并从原入口拖动植物。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 满足父spec的最小工厂interface：一个共享加载/分类/组装实现，一个共享离线prepare与calibrate实现；正式通用CLI以scene选择声明，旧alocasia命令为薄兼容入口，错误含场景名及诊断。
- [ ] alocasia已接受的r、elementSize、材料、柔抓、变换、完整背景和标签延拓全部保持；工厂只把真实变化项留在小配置中，不新增求解器或绑定分支。
- [ ] 核对父spec中的真实相机差异，修正up检查使合法强俯拍不被误称为错误世界up。保留逐帧原始角和矩阵合法性，最终阈值/定义有依据；最小方案可改现有判据或在必要时引入模式，记录选择理由，不仅放宽到92°。旧alocasia检查兼容，合成错误坐标轴、倒置、无证据仍可诊断。
- [ ] 无固定材料是否可接受由明确场景声明决定；校准和运行时一致。空材料/空moving/无可动材料失败；alocasia仍要求固定支撑。不为了未来可能性新增固定区域算法。
- [ ] 共享变换及资产原输入保护、最后发布report、失败失效旧产物、报告scene/声明/出处、场景输出隔离保持。原资产与衍生产物均不入git。
- [ ] 测试共享interface的三分法、清洗、节点标签延拓、配置独立性、全动合法声明/错误诊断、旧CLI兼容和up判据。现有alocasia相关回归及架构/文档护栏通过；依赖入口改名同步护栏并写ADR，新增代码目录同步架构。
- [ ] 在当前Intel UHD770打开 `?scene=alocasia`，真实资产出画面并完成一次抓取/松手，记录命令、画面证据与实际结果；无需重跑旧08全部矩阵。实际新增场景注册留给后续票。
