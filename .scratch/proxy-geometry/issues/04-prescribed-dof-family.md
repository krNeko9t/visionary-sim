# 04 · 「被规定的自由度」这一族的名字

Status: open
Type: grilling
Blocked by: 01, 02

## Question

给今天挤在 `invMass === 0` 这一个编码里的几样东西定名，并把**不属于这一族的那个踢出去**。

工作假设（由 01 核实，由 02 提供证据）：

- `invMass = 0` 是一种**编码**，不是一个概念。词汇表里不该有「逆质量为零」这个词条。
- 真正的概念只有一族：**位移被外部规定、不由求解器解出的自由度**。仓库今天有它的临时版
  （`setPrescribed`，有持有者、松手归还），缺它的永久版（锚定）。
- **惰性节点不是这族的第三个成员**——它是稠密点阵的填充产物，换成无结构网格就不存在。它的位置
  是 `ARCHITECTURE.md` 4.2 的后果表，不是词汇表。

要决定的：

1. 这一族叫什么（用 01 带回来的共识词，不自创）；
2. 「永久 / 临时」是这一族里的两个词条，还是同一个词条的两种生命周期；
3. 惰性节点确认踢出之后，它在代码里还该不该和真·被规定的自由度共用 `invMass = 0` 这个编码——
   共用是不是本来就是那三种含义纠缠的根因；
4. `CONTEXT.md` 首批还要收哪些词条：模拟体、代理几何、自由度、约束、驱动、场景/环境……
   收的标准是「领域概念」，不是「代码里出现过的名词」。

## 交付

- 新建 `CONTEXT.md`（`docs/agents/domain.md` 要求懒创建，这张票就是第一次有东西可写）。格式见
  `.claude/skills/domain-modeling/CONTEXT-FORMAT.md`。
- **纯词汇表**：不含实现细节、不含决策理由、不当规格书用。
- 定名的**理由**不写进 `CONTEXT.md`，写成一条 ADR。
