# 04 · 「被规定的自由度」这一族的名字

Status: resolved
Type: grilling
Blocked by: 01, 02

## Question

给今天挤在 `invMass === 0` 这一个编码里的几样东西定名，并把**不属于这一族的那个踢出去**。

工作假设（由 01 核实，由 02 提供证据）：

- `invMass = 0` 是一种**编码**，不是一个概念。词汇表里不该有「逆质量为零」这个词条。
- 真正的概念只有一族：**位移被外部规定、不由求解器解出的自由度**。仓库今天有它的临时版
  （`setPrescribed`，有持有者、松手归还），缺它的永久版（锚定）。
- **惰性节点不是这族的第三个成员**——它是稠密点阵的填充产物，换成无结构网格就不存在。它的位置
  是 `ARCHITECTURE.md` 4.2 的后果表，不是词汇表。

要决定的：

1. 这一族叫什么（用 01 带回来的共识词，不自创）；
2. 「永久 / 临时」是这一族里的两个词条，还是同一个词条的两种生命周期；
3. 惰性节点确认踢出之后，它在代码里还该不该和真·被规定的自由度共用 `invMass = 0` 这个编码——
   共用是不是本来就是那三种含义纠缠的根因；
4. `CONTEXT.md` 首批还要收哪些词条：模拟体、代理几何、自由度、约束、驱动、场景/环境……
   收的标准是「领域概念」，不是「代码里出现过的名词」。

## 01 已经带回来的（2026-09-20）

- **族名候选在手**：`prescribed`，下分 `static prescribed`（永久、无持有者，原「锚定」）与
  `kinematic prescribed`（临时、有持有者，`KinematicDrive`）。采纳成本为零：
  `setPrescribed`/`clearPrescribed` 已经存在，`ARCHITECTURE.md`§三已经写着「被**规定**而非被
  **解出**」。行业**没有**单一伞形词，Box2D / PBD / PhysX / Vellum 都是在顶层就分成
  static 与 kinematic。所以这张票要决定的不再是「叫什么」，而是：接受这个二分，还是自创一个
  伞形词把两者收进去（后者违背「往共识靠」）。
- **仓库内部撞名**：`anchor` 已经被占用了，而且恰好是行业含义——`grip.js:38,54`、
  `simulator.js:389-411`、`drive.wgsl:22` 用它指「射线打中的那个节点」，即约束的附着点。这条
  撞名本身就该是词汇表第一批条目之一。
- **`inert` 有共识词**：`inactive node`（MPM 文献）。预判「外部没有对应词」被推翻，但**下游判断
  不变且被加强**——没有任何来源把它归进边界条件一族，稀疏 MPM 的存在就是为了删掉这种节点。它
  仍然是 4.2 的后果，不入 `CONTEXT.md`。这张票多一个决定：代码里那个自造的 `inert` 要不要改名
  成 `inactive`。

## 交付

- 新建 `CONTEXT.md`（`docs/agents/domain.md` 要求懒创建，这张票就是第一次有东西可写）。格式见
  `.claude/skills/domain-modeling/CONTEXT-FORMAT.md`。
- **纯词汇表**：不含实现细节、不含决策理由、不当规格书用。
- 定名的**理由**不写进 `CONTEXT.md`，写成一条 ADR。

### 〇、先修正这张票自己的前提

**「三样东西挤在 `invMass === 0` 一个编码里」——今天只挤了两样，而且缝已经划在对的地方。**
`particles.js:79` 的 `this.invMass` 是**材料真相**（零 ⟺ 惰性），`particles.js:88` 的
`this.gpuInvMass` 是**此刻不被解算**（惰性 ∪ 被规定），两者由 `uploadGpuMasses()`（`:188-196`）
**单向合成**而不是就地覆写。`pick.js:36` 与 `grip.js:108` 读的是前者，注释「A node with no
material never moves」**今天是真话**。真正无家可归的是还不存在的那个：静态规定（锚定）。

这条改变了第 3 问的答案：共用编码**不是**纠缠的根因（见下 §三）。

### 一、族名（第 1 问）

**收伞，族名 `prescribed`。** 01 查实行业没有伞形词（Box2D / PBD §3.6 / PhysX / Vellum 都在顶层
就劈成 static 与 kinematic），收伞是一次轻度自创，判据是**本仓库有一个上游没有的需求**：
`gpuInvMass` 是一个真实存在的合成数组，它需要一个名字，今天靠 `particles.js:81-85` 一整段注释在
绕过这个缺名。上游不需要伞，是因为它们没有做这次合成。代价如实记进 ADR-0002。

### 二、static / kinematic（第 2 问）

**两个词条，分界轴是归属不是时长。** 静态规定属于**物体**（随离散化确定，没有持有者，因而没有
任何东西可以松手），运动学规定属于**一次交互**（持有者存续期间喂目标，松手即归还）。
「永久 / 临时」是从归属推出来的**后果**，所以 `CONTEXT.md` 里一个字都不写——写了会让人以为时长
是原因。Vellum 的 Permanent / Stopped 是同一判断的判例。

### 三、编码（第 3 问）

**规则：材料数组里的零只表示惰性；被规定的自由度从不写进材料数组。** 锚定落进第三个位置（与
`prescribed` 并列、一起合成进 `gpuInvMass`），不落进材料 `invMass`（那会让 `pick.js`/`grip.js`
当场变成假话），也不落进现有的 `prescribed` 集合（那个集合「一次一个 driver、直接替换上一批」，
第一次抓握就会把锚定擦掉）。

**所以第 3 问的答案是否定的**：共用一个编码不是纠缠的根因，**把不同归属的东西写进同一个数组**
才是。机制落点（改哪个文件、第二个集合长什么样）仍归锚定那张图，这里定的是它必须满足的语义
约束。详见 ADR-0003。

### 四、方向性

**是这一族的一个维度，不是第三个成员**，且 `CONTEXT.md` 的族定义**对方向性保持中立**——写成
「位移由外部规定、不由求解器解出的自由度」，既不承诺也不排除「只在某个方向上被规定」。这样
将来换 3×3 质量矩阵改的是实现，不是定义（改定义是词汇表最贵的一种改动）。

grilling 第一轮我把这条摆成了「保守 vs 激进」的两难，那是我造出来的——两难的来源是我把定义写成
了「位移**在某些方向上**被外部规定」，去掉那五个字，代价当场消失。

### 五、`inert` → `inactive`（01 追加的那条）

**词定为 `inactive`**（01 给出 MPM 与 fictitious-domain FEM 两处出处），**改名动作路由给 06**。
核实：`inert` 在 `src/` 里只出现在注释与 jsdoc（`lattice.js:9,16,18,114`、
`particles.js:27,28,66,81`、`pick.js:22`、`grip.js:86`、`voxelize.js:190`），**没有一个标识符叫
这个名字**，是一次纯注释替换。本图 Notes 给 `src/` 的许可是「护栏红转绿所需的最小改动」，注释
改名不是红转绿；而那六个文件里有四个本来就在 02 的清单上、要随 06 那一趟动。04 只交出「哪个词
是对的」。

### 六、`CONTEXT.md` 首批（第 4 问）

**判据：只收有歧义或已撞名的词。** 收了 9 条，分两组：

- **几何与自由度**：代理几何、模拟体、节点、自由度
- **自由度要服从什么**：约束、被规定的自由度、静态规定、运动学规定、锚点

**「节点」与「自由度」拆成两条**是这批里唯一一处主动挑刺：§三写「`sim/state/` 自由度」，代码
里的单位却是节点（一个节点三个自由度）。四定完方向性是维度之后，这两个词**不能再混用**——
方向性讲的恰恰是一个节点的三个自由度可以分开处置。节点是几何侧的单位（接触、瞄准、插值），
自由度是求解侧的单位。

**「约束」必须收**，因为 §三 给了它一个比行业窄的定义（只有进入派发序列的才算），01 正是因为
这条才否掉 `constrained` 做族名。不写下来，下一个人会用行业的宽义。

**「锚点」必须收**，它是防止未来把 `anchor` 用去指静态规定的路障。

**这轮不收的**：材质、静止形状（是领域概念，但今天没有歧义也没有撞名——没有争议的词进词汇表，
只会让人以为词汇表是目录）；惰性节点 / `inactive node`（01 查实它有共识词，但两边文献都把它归
为离散化产物与要被消灭的开销，从不归进边界条件一族——它是 4.2 的后果，不是领域概念）。
