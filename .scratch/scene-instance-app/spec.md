# 场景级实例物性应用：纯前端实现规格

ID: scene-instance-app-spec
Status: needs-info
Assignee: unassigned
Date: 2026-09-09

## Problem Statement

用户已有完整高斯场景、实例标签和上游物性结果，希望在网页中观察完整场景，校正其物理尺度和朝向，选择实例并让它们共同模拟、接触和接受抓取，同时保留其余场景作为视觉参照。

当前演示与单实例原型尚未提供正式的文件关联校验、多实例追加及配置保存恢复闭环。直接复用逐物体居中缩放会破坏实例相对布局；重建模拟会丢失已有物体状态；两轴高斯还需要显示与体素占据适配。用户需要能处理真实输入、清楚报告失败并保留已有成果的正式入口。

## Solution

提供纯前端的场景实例工作台，采用已认可的 A 双侧布局。用户通过三个文件槽导入已有结果，先看到完整场景和实例信息，再完成全局校正与六面场景容器编辑。实例仅在用户加入时准备模拟资源；加入成功后自动运行并开启抓取，追加实例保留已有模拟体的状态。

物性可随时编辑；全局暂停保留运行状态，返回准备则恢复源布局并保留准备配置。用户可手动本地保存或导出轻量配置，重开并重新关联源文件后回到准备状态。首版容器在准备阶段编辑、运行时静止，所有数据处理留在浏览器内。

## User Stories

1. As a 场景使用者, I want to 在三个明确文件槽选择几何、标签和物性结果, so that 我可以直接使用已有上游产物。
2. As a 场景使用者, I want to 在本机浏览器完成解析和准备, so that 场景无需上传或交给应用后端计算。
3. As a 场景使用者, I want to 在启动时获知所需运行能力是否可用, so that 无法运行时有明确原因。
4. As a 场景使用者, I want to 看到文件损坏、长度错配和重复实例身份的具体错误, so that 我能修正输入。
5. As a 场景使用者, I want to 导入失败或取消后仍保留原场景, so that 一次尝试不会破坏已有工作。
6. As a 场景使用者, I want to 看到完整场景及未追踪内容, so that 观察时保有真实的空间参照。
7. As a 场景使用者, I want to 用实例着色检查标签对应关系, so that 我能发现结构检查无法识别的同规模错配。
8. As a 场景使用者, I want to 在场景中点选或从实例列表选择对象, so that 可见及被遮挡实例都能被检查。
9. As a 场景使用者, I want to 查看实例身份、名称、上游物性和当前覆盖值, so that 我知道正在编辑哪个对象及其生效参数。
10. As a 场景使用者, I want to 缺失物性的实例仍可显示并补齐参数, so that 局部数据缺失不阻止观察其他实例。
11. As a 场景使用者, I want to 导入时不为全部实例生成模拟资源, so that 我只为需要交互的对象进行准备。
12. As a 场景使用者, I want to 看到准备阶段、可用计数和取消入口, so that 我可以理解并控制较长的准备过程。
13. As a 场景使用者, I want to 选择源上轴并手工调整朝向, so that 场景与世界向上的方向一致。
14. As a 场景使用者, I want to 设置全场景参考最长边的米制长度, so that 模拟采用我指定的物理尺度。
15. As a 场景使用者, I want to 绕场景中心统一旋转、缩放和平移, so that 实例间的相对布局保持不变。
16. As a 场景使用者, I want to 使用固定世界网格和世界 +Y 相机, so that 校正时有稳定的观察参照。
17. As a 场景使用者, I want to 初始六面容器包住完整场景, so that 模拟体有明确的内部活动区域。
18. As a 场景使用者, I want to 用同一 gizmo 和数值输入平移、旋转及调整容器三轴尺寸, so that 边界编辑方式一致。
19. As a 场景使用者, I want to 独立编辑容器而不移动内部实例, so that 我能改变活动区域而保持场景布局。
20. As a 场景使用者, I want to 收到初始越界提示且抓取目标受容器限制, so that 边界行为可以理解。
21. As a 场景使用者, I want to 将物性有效的实例加入模拟, so that 它能够运动和形变。
22. As a 场景使用者, I want to 加入成功后立即运行并可抓取, so that 不必重复点击继续和开启抓取。
23. As a 场景使用者, I want to 追加实例时已有物体保留位置、形变和速度, so that 可以逐步建立共同模拟。
24. As a 场景使用者, I want to 新旧模拟体相互接触并受容器六面约束, so that 它们在同一个物理场景中演化。
25. As a 场景使用者, I want to 仅渲染内容不自动参与碰撞, so that 参与模拟的范围由我明确选择。
26. As a 场景使用者, I want to 追加失败或取消时原实例仍显示、已有物体保持冻结状态, so that 我可以修正后重试。
27. As a 场景使用者, I want to 随时修改物性而不重置形状和速度, so that 可以直接观察参数变化。
28. As a 场景使用者, I want to 准备期间的物性修改也在提交时生效, so that 不会悄悄使用过期参数。
29. As a 场景使用者, I want to 暂停和关闭抓取, so that 可以稳定观察当前状态。
30. As a 场景使用者, I want to 明确看到模拟慢于现实时间的情况, so that 不会把算力预算限制误认为重力或材料被修改。
31. As a 场景使用者, I want to 返回准备后恢复源布局并保留配置和参与名单, so that 能重新校正和开始实验。
32. As a 场景使用者, I want to 手动保存准备配置并导出 JSON, so that 可以在后续会话恢复编辑成果。
33. As a 场景使用者, I want to 重新选择改名或移动后的相同文件仍能恢复配置, so that 文件位置变化不丢失关联。
34. As a 场景使用者, I want to 同名不同内容的文件作为新场景处理, so that 旧实例参数不会误套到其他场景。
35. As a 场景使用者, I want to 重开后停留准备状态并由我点击开始, so that 恢复配置不会自动触发模拟。
36. As a 场景使用者, I want to 保存失败、配置损坏或版本不支持时得到明确反馈且当前编辑保留, so that 可以修正或导出备份。
37. As a 场景使用者, I want to 无派生缓存时仍能重新准备, so that 缓存丢失不会阻断使用。
38. As a 项目维护者, I want to 新应用与既有演示共用模拟和形变渲染内核, so that 上游格式变化不会蔓延到求解器。

## Implementation Decisions

以下综合已解决决策；后续修订优先于早期票中的被撤回条款。

1. **应用边界。** 新增应用层管理会话、实例目录、选中项、准备配置及实例与模拟体、视图的关联；应用专属准备模块解释上游格式并组织 Worker。入口只选择和启动应用，既有演示也由应用入口装配。UI 接收状态与操作回调，不接触粒子缓冲；场景模块保留观察环境与既有场景描述。
2. **内核边界。** 资产模块只复用无上游语义的基础能力；物体模块描述材质和分离的模拟、渲染几何。模拟模块拥有共同演化、状态迁移和资源生命周期，对外提供不透明稳定模拟体标识。渲染与形变模块拥有视图准备、替换、绑定和释放，新表示继续走既有唯一形变绑定通道。下层不反向依赖应用，不建设插件或通用导入框架。实施新增源码目录时同步架构表与依赖测试表，依赖理由追加到决策记录。
3. **输入与平台。** 首版验证桌面 Chrome/Edge，并检测实际 WebGPU 等运行能力。三个槽分别接受源 PLY、包含 NPY 数组的标签 NPZ、实例物性 JSON。NPZ 必须解码 ZIP 容器及数组，不能把解压流当作完整解析器。用户选择文件授予访问权，本机路径及历史服务器路径不构成网页读取权限。
4. **关联校验。** 在原始高斯行序上检查必要字段、数组类型和长度、labels/valid 关系、正实例 ID 唯一性及可用 n_gau 计数。结构损坏或明确关联矛盾拒绝整次导入，说明文件与原因。单实例物性缺失或不合法则保留显示和选择，仅阻止该实例加入，补齐后可重试。结构通过不宣称三件套已证明同源，提供实例着色供核查。
5. **完整场景与身份。** 标签 0 为未追踪内容，valid=false 也不代表无效几何，均不得据此删除显示内容；未追踪内容仅渲染。正 ID（包括墙、地板）一视同仁。任何筛选或重排同步携带原始行映射，计数校验在清洗前执行。不新增过滤阈值、不套用逐实例居中缩放落地。身份限定为源数据组合内的上游实例 ID，名称和数组下标不充当身份。
6. **按需准备。** 导入生成完整两轴渲染数据、实例映射、拾取与着色索引、目录和物性校验结果，模拟体数为零。加入时才生成该实例体积代理、晶格、模拟资源及绑定。CPU 解码、关联检查和适合后台的准备交应用专属 Worker；阶段无法度量时不伪造百分比。取消使任务失效并停止后台工作，迟到结果不得提交。失败报告阶段和原因，可修正重试；不自动重复失败任务。
7. **两轴表示和体积。** 显示接入 PlayCanvas 的 2DGS 能力；模拟以二维椭圆片与体素相交覆盖标记表面占据，复用膨胀封缝、外部 flood fill、内部填充、腐蚀回退并回并原占据及晶格生成。保留显示高斯中心所在格占据的绑定约束。不把第三轴置零后继续执行除半轴判定，也不把数值覆盖容差当作真实厚度。质量采用密度乘近似占据体积；不要求用户补真实厚度或预先拒绝所有两轴实例。漏填、误封和薄片问题以实际结果验证。
8. **米制校正。** 参考包围盒来自准备后保留的全场景有效高斯中心，包含仅渲染内容；其中心为固定支点，最长边为固定基准。默认最长边代表 1 米，用户可设有限正长度 L；这不表示测得真实尺寸。平移表示校正后场景中心的世界位置，初始原点，不自动落地。空场景、非有限范围或零最长边不能开始模拟。选择或加入实例、编辑容器不重新计算基准。
9. **朝向约定。** 世界右手系、米制、Y 向上，重力恒为世界 (0,-9.81,0)。先对源点减参考中心，再应用源上轴预设、手工旋转、统一比例 L/参考最长边，最后加世界平移。六种上轴预设分别采用：+Y 恒等、-Y 绕 X 180°、+Z 绕 X -90°、-Z 绕 X 90°、+X 绕 Z 90°、-X 绕 Z -90°。手工按固定世界 X、Y、Z 轴顺序旋转；配置为绝对值，从参考数据重算，切换预设保留手工角、尺度和平移。不用软件品牌命名预设或猜测手性。
10. **空间一致性。** 中心、轴向/法线、自身轴长及方向相关外观随全局变换一致变化；两轴表示保留维度。显示、代理、拾取和形变使用一致空间。密度 rho_si（kg/m³）、杨氏模量 E_si（Pa）、泊松比 nu_si（无量纲）不随几何尺度改值；尺度改变使体积、质量及相关缓存失效。上游不确定性字段不冒充 SI 误差条，trust 不冒充物性准确性证明。
11. **观察与编辑。** 采用 A 双侧工作台，世界参考网格固定 Y=0、仅作视觉参考；相机 up 固定世界 +Y，源相机只提供取景位置和方向，不与重力一起乘场景校正。支持场景点选及列表选择；协调相机、gizmo、选择和抓取的指针归属，避免一次操作触发多个动作。
12. **六面场景容器。** 一个可旋转封闭长方体，内部可活动，六面含顶面均产生朝内接触。初始包围完整场景；全局校正带动容器，独立容器编辑不变换实例。gizmo 和数值输入共同修改同一位置、正交朝向和有限正内部尺寸；三轴缩放只改容器尺寸。首版仅准备阶段编辑，运行时静止；再编辑需返回准备。初始越界明确提示，不静默移动源场景适配；抓取目标限制在容器内部。
13. **容器接触。** 按容器平移和朝向将节点转入局部空间，对正负半尺寸六面处理接触，再将修正转回世界。非等比尺寸不混入旋转或法线变换；若沿用原型的容器刚体坐标求解，重力和形变亦正确换空间。内侧边界、接触粗筛范围与观察范围分离，验证旋转及边缘桶候选完整性。既有敞口演示保持原行为。
14. **追加冻结与状态。** 加入前在完整物理步之间冻结共同模拟，保留已有位置、形变、速度、静止几何和当前物性；结束抓取并使在途抓取失效。候选准备期间新实例仍静态显示，旧体保持冻结形状。新体从校正后的源布局、零初速度加入，不暗移旧体避开重叠。仅渲染内容不碰撞；提交后新旧体和容器共同接触。
15. **整体发布与资源所有权。** 模拟内部准备候选并迁移旧体状态，不把变形位置当作静止形状；应用不搬运粒子。渲染准备新视图与既有模拟体必要的改绑。所有可失败步骤及最新物性同步完成后，统一发布模拟状态、绑定、视图和实例关联，成功后由资源所有者释放旧资源。发布前失败或取消只清理候选，保留旧模拟与显示，不出现双份表示、实例消失或旧绑定引用已释放缓冲。导入替换也遵守保留旧场景的契约，不保证任意设备可同时容纳两套大场景。
16. **成功、失败与时钟。** 加入成功自动运行并开启抓取；失败或取消保持暂停、旧体冻结、新体仅渲染，允许重试。三种结果均保留已有模拟时钟账目与未消费小数时间，准备耗时不计积压、不追赶；清除未执行单步请求。重试产生新任务身份。
17. **物性编辑与步长。** 上游原值和当前生效值分开展示，不截断到演示滑块范围、不静默软化。运行、暂停及准备期间均可修改有效物性，不重置形状与速度。提交前同步最新质量、约束和共同步长；最新值不合法则拒绝发布。沿用全场最严格波速/格距比确定固定步长（上限 1/240 秒、CFL 0.75），每帧最多 24 步。超预算沿用丢时并报告模拟慢于现实时间，不放大物理步长。
18. **返回准备。** 终止演化和抓取，使旧任务失效，释放模拟与绑定资源，恢复全局校正后的源布局和未变形表示，清零速度与模拟时钟。保留源引用、实例身份、参与名单、物性覆盖、当前全局校正及最新容器配置。运行时修改全局校正必须先执行此流程；再次开始按名单重新准备。不提供另一种含糊的重置语义。
19. **准备配置。** 手动本地保存并支持轻量 JSON 导出、导入。配置含格式版本、三个源槽的完整字节 SHA-256 与便于重选的文件名、全局校正、最新容器配置、按上游 ID 关联的物性覆盖及参与名单。排除源大文件、运行位置偏移、形变、速度和运行时模拟体标识。配置完整校验后再替换，损坏、未知版本或无效实例引用不得部分应用。
20. **恢复与文件关联。** 重开先读配置，无源访问权则提示重新选择。三槽内容相同且校验通过才恢复配置，改名或移动不影响关联；任一槽内容不同作为新场景导入，不自动套旧配置。指纹只证明与保存时一致，不证明初始三件套同源。恢复停留准备状态，用户点击开始才准备名单中的模拟资源，并遵守整体提交和失败保留契约。
21. **缓存与存储失败。** 首版仅会话内可重建缓存，依源内容、相关参数及转换策略版本判定复用，依赖变化丢弃受影响结果。无缓存也可导入及按需准备；资源不足先释放可重建缓存，仍失败则明确报告且保留旧场景。本地保存失败不显示已保存，保留内存编辑并允许导出。浏览器记录被清理后依导出副本恢复，不承诺永久存储。

## Testing Decisions

测试边界方案待用户核对；其余功能范围来自已解决决策。

- **主要边界：应用公开操作与可观察会话状态。** 在同一个应用会话边界调用导入、选择、校正、编辑、加入、暂停、返回准备、保存和恢复，验证状态、可见表示、配置及错误结果。应用层尚未正式建立，这是随既定应用模块新增的一处高层边界。文件、Worker、存储及模拟/显示候选端口可提供受控失败或迟到结果；不按内部方法调用顺序或私有缓冲布局写测试，也不为测试单独拆通用框架。
- **真实内核验证。** 应用边界的替身只能证明流程契约；多体状态迁移、改绑、六面接触及显示形变必须以真实 Simulator、形变绑定和渲染在 WebGPU 浏览器中验证。在追加前后同一冻结时刻比较旧体位置、速度和静止参考行为；继续后观察接触和形变，不能仅凭 UI 显示“运行中”判定通过。
- **现有先例。** Vitest 的 simulatorTiming、timestep 已从模拟公开时序入口检验暂停、固定步长和材质更新；assets、splats 检验输入与映射相关基础行为；cloudVolume、voxelize、discretize 检验占据和晶格；pick、grip、contact 检验拾取、抓取和接触；renderPaths、architecture、docs 检验绑定和架构约束。优先复用这些已有边界，仅对新增数学行为补有判别力的回归，不逐模块重复应用流程测试。

## Out of Scope

- 在网页运行或重做上游实例识别、物性推断流水线；应用后端、服务端计算或自动上传场景。
- 目录自动发现、两点测距、逐实例归一化、任意非等比场景变形，以及无依据的坐标品牌预设。
- 多个实心障碍盒、任意形状容器、运行时动态容器拖动/挤压及运动学接触；这些不作为首版验收阻塞项。
- 单实例退出模拟、删除模拟体或单体暂停。
- 保存或恢复运行中形变、速度和模拟进度；自动保存、多项目管理、通用配置迁移及持久派生缓存。
- 每帧预算调优、GPU 余量研究、性能控制面板、未经测量的设备资源或实时性能承诺。
- 通用插件平台、统一所有上游的导入格式，以及新增重建、采集或逐实例手工代理工作流。
- 本次规格任务不实施功能、不部署；正式实现以本规格和其验收为后续工作。
