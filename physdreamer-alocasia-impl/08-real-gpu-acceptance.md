# 08: 在目标 GPU 验证真实 alocasia 的交互、静态性与实时预算

**What to build:** 在真实资产及已校准参数下，完成可复查的目标设备运行验收，证明花盆/盆土严格静止、叶片可交互，并符合现有求解预算。

**Blocked by:** 07 — 真实资产校准；外部条件：可运行本应用的目标 WebGPU 设备及实际交互/画面/状态观测能力。

**Status:** ready-for-agent

- [ ] 记录设备、GPU、浏览器、运行条件、资产标识、最终 r、elementSize、材料与观测时间。打开 ?scene=alocasia，植物/花盆可见、重力为零，无房间背景和玻璃缸，现有材质、抓取半径和代理线框控制可用。
- [ ] 拖叶片时观察叶柄弯曲、松手回弹并逐渐停止；分别验证硬/柔抓取、驱动切换、松手、改密度、重置之后静态节点及固定高斯中心/旋转/尺度不变。保存数值前后对照与可复查图像/录像或等价证据，不只凭截图推断位置恒定。
- [ ] 核查静态节点无法作为锚点或进入握持球，射线能继续寻找合格节点；固定接触节点仍对其他物体产生响应（可另用合成双体 GPU 案例），不能以零逆质量或 CPU mock 替代 GPU 行为证据。
- [ ] 检查叶柄连接、薄结构、封口桥接/过厚和静动接缝，保留线框与真实几何对照。不以体积占比三成为硬阈值，不读点阵内部 volume；发现桥接/过厚需报告证据重开选择，不能静默调 r 或填充参数补救。不承诺当前不存在的自接触。
- [ ] 在目标设备按 60 fps 条件记录实测 cfl < 1、每帧 steps <= 24、droppedTime == 0，以及实际帧率/时间与 cflLength。0.75 安全系数、1/240 上界和 c/cflLength <= 1080 s⁻¹ 的理论预算不能替代实测；不得提高每帧上限。
- [ ] 完成全套相关行为测试、architecture.test.js、docs.test.js 和构建，记录命令、结果及任何未通过项；修复实现缺陷后重验受影响行为，不放宽点阵知识边界。
- [ ] 将最终实测与验收结论记在本票/原 spec；只有 01–08 所需行为、真实校准和 GPU 证据全部通过才宣布接入完成。缺资产、设备、观测能力或验收失败均如实保留为未完成，不以理论、历史或合成证据替代。

依据原 spec「真实数据与 GPU」「文档与交付边界」。不扩展到其他 PhysDreamer 场景、逐点材料、学得初速度/冲量、运行时锁定/解锁；DECISIONS.md 保持只读。
