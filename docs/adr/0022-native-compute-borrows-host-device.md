# 原生计算后端借用宿主 device，提交不依赖渲染帧

替代 [ADR-0009](0009-playcanvas-renders-webgpu-compute-simulates.md) 中由 PlayCanvas 提供物理缓冲、着色器处理和计算派发的决定；实验应用继续由 PlayCanvas 渲染。Visionary 宿主不能依赖 PlayCanvas，因此模拟器只接收宿主已有的原生 `GPUDevice`，不请求或销毁 device。

`sim/compute` 是内核私有的薄计算边界，由 `Simulator` 组装并交给状态与约束；这些模块不再借用引擎 API。后端集中分配、上传、读回和独立提交，WGSL 明确声明绑定与参数结构，显式 pipeline layout 与参数名检查使错误在计算前可见。小型参数布局读取器只接受现有 kernel 的标量和三维向量类型；不引入通用着色器转译器，也不在 JS 复制一份参数顺序表。单元测试替换这道边界为内存后端；原生后端另以伪造 device 和真实 GPU 数值关卡验证。

宿主先步进再绘制，同一队列保证宿主读取本次结果；暂停渲染时仍可单步与抓取读回。计算缓冲由模拟器释放，映射暂存缓冲在成功或失败后都释放。构造失败也释放已经分配的缓冲。旧形变字段暂时传原生缓冲，应用通过 `render/playcanvasInterop.js` 包装给 PlayCanvas；正式形变清单留给后续接口工作。

求解顺序、固定步长、物理输入与浮点表达式保持原样。此阶段必须先通过三个旧参考的零容差比较，再引入会改变节点集合的协方差输入。
