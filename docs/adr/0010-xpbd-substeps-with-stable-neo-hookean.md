# XPBD 子步 + 稳定 Neo-Hookean，杨氏模量与泊松比是一等参数

立项时紧接着 [ADR-0009](0009-playcanvas-renders-webgpu-compute-simulates.md) 的决定，理由与
替代方案同样没有记录。事后兑现的是两件：XPBD 让每一种约束各自投影、互不知情，§三「求解器叫
不出约束的名字」建立在这上面；稳定 Neo-Hookean（Smith 等 2018）让用户调的是杨氏模量与泊松比
这两个有物理含义的量。

换掉它要重写 `sim/solver/` 与 `sim/constraints/`；只在 XPBD 下成立的量（顺服量、gamma、CFL）
都收在这两个目录里。

## Consequences

只列跨模块、在屏幕上看得见的后果。

- **渲染帧只决定何时提交，不决定一次物理步有多长**。求解器按最坏材料与各物体的 `cflLength`
  选定固定量子；浏览器帧长只改变本帧跑几个量子，追不上的整量子被显式计为丢时，从不靠放大
  `dt` 把过载伪装成实时（上限与推导在 `sim/solver/timestep.js`）。
- **两条越界即塌的边界，属于不同的层**：CFL 属于求解器，加子步能救；塌陷势垒属于本构模型，
  加子步没有用。界面把两个当前值摆在会推着你越界的滑杆旁边（`ui/panel.js`）。
