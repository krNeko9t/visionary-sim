# 物体之间的接触用边界节点上的球并集

一个物体在接触里被当成一组球：每个边界节点一个球，球并集就是它的外形。两个物体相互推开，就是
球与球互相推开。这是粒子类引擎（Flex、Macklin 等 2014 年的 unified particle physics、PBD 一系）的
做法，不是物理引擎的通用答案；网格类引擎（有限元软体、IPC）检测的是表面三角形之间「点撞面、
边撞边」。

这个选择原本不是选出来的，是体素点阵（ADR-0005）顺手给的：点阵节点等距，半格的球恰好密封，
不需要表面网格。它现在被单独记成一个根，因为它**不随点阵走**：换掉点阵不必换掉它，换掉它也
不必换掉点阵。

## Considered Options

- **表面三角形接触**。接触精度跟着表面走，不会留缝，也不要求密封。否掉的只是「现在做」：它是
  另一套窄相，重写 `sim/constraints/` 的接触部分，比代理几何的重构本身还大。

## Consequences

- **两个静止物体之间约留一个节点间距的缝**。这是球的厚度，不是求解器误差，要消除它就得换表面
  表示，不是调求解器。
- **球必须密封**：相邻边界球两两相接，另一个物体的节点才不会从缝里穿过去。这是**球模型**对
  代理几何提的准入条件，不是代理几何本身的规律。代理几何接口里「交出边界节点和每个节点的
  半径」那一条的形状由本条决定：换接触模型时，那一条跟着改。
- 节点间距不均匀的网格（四面体）上，球很难同时做到既密封又不把物体撑胖，薄处、尖角处尤其难。
  第二个离散化后端若交不出密封半径，就接不进这个接触模型，那时应该换的是接触模型。
