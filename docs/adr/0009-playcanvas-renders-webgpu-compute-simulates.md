# PlayCanvas engine 承担渲染与场景，物理以 WGSL compute 跑在 WebGPU 上

立项时的决定，是整个项目的底座。当时选它的理由与比较过的替代方案都没有记录下来（封存的
`DECISIONS.md` 从 2026-08-07 才开始）。事后兑现的是：浏览器里既要画 3DGS、又要每子步解全部
节点的软体，渲染与物理都落在同一块 GPU 上，物理的缓冲区直接借引擎的 device 分配。引擎不带
软体，物理是自己写的：`sim/` 用到的引擎 API 只有缓冲与派发，求解器的数学（顺服量、时间步、
接触网格）是纯函数，在不启动引擎的单元测试里核对。

换掉它等同于换项目。

## Consequences

只列跨模块的后果；只在 `render/` 里才看得见的（标准材质的顶点钩子、高斯形变插在 work buffer
那一趟、`render/ellipsoid.js` 的特征值分解、显式选 GPU 排序）写在那些文件的头部注释里。

- **两个 `wgsl/` 目录不受这个选择约束**：那些着色器除了方言（`uniform x: T;`、storage 绑定交给
  引擎分配）之外可移植，换引擎是机械替换，不是重写物理。
