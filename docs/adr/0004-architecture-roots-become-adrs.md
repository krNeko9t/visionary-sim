# `ARCHITECTURE.md`§四的根逐条转成 ADR，后果留在代码旁边

§四曾把每个可换的选择连同它逼出的全部细节写在一处，结果越长越像代码库的有损压缩，把§一到
§三的核心设计挤成配角。改为：每个根是一条 ADR，只写选了什么、为什么、以及**跨模块才看得见**
的后果；只对打开某一个模块的人有用的后果，写在那个模块的代码旁边——审计
（[02](../../.scratch/proxy-geometry/issues/02-tetrahedral-counterfactual.md)）撞出的 4.2 九条
「漏网假定」本来就都在源码注释里，§四只是在抄一份会过期的副本。「换掉要动什么」不再写成
文字：它描述的是会变的现状，4.2 那一句已经错了两次；它的真相是离散化词表测试（只有实现所在的
目录可以说实现的词）。

## Considered Options

- **保留§四，把九条假定补进 4.2 的后果表**（本次改动之前的计划）。否掉：正是让它变长的那个动作。
- **把 4.2 拆成上下两层根**。否掉：多一层缩进，内容一条不少。

## Consequences

- 推翻了 proxy-geometry 图早先划下的边界「不把§四拆成 ADR，平铺 ADR 表达不了根→后果」。那条
  理由不成立：跨模块的后果很少，ADR 之间互相引用就够；需要树形结构的其实是模块内部的后果，而
  它们本来就该待在模块里。
- 4.2 先转（[ADR-0005](0005-voxel-lattice-proxy-geometry.md)），其余各根另行转换。转完之后
  `ARCHITECTURE.md` 只剩目的、目录表、结构承诺与护栏表。
