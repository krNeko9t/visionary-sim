# 材料逆质量数组里的零只表示惰性，被规定从不写进它

`Particles` 持有两个逆质量数组：`invMass` 是**材料真相**，`gpuInvMass` 是**此刻不被解算**，后者
由 `uploadGpuMasses()` 从前者加上被规定集合**单向合成**。这条缝今天划在对的地方：`pick.js:36` 与
`grip.js:108` 读的是材料数组，它们的注释「A node with no material never moves」因此是真话。

还不存在的**静态规定**（锚定）有三个可能的落点，我们选第三个，并把它定成一条规则：**材料数组里
的零只表示惰性节点；被规定的自由度——无论静态还是运动学——从不写进材料数组。**

## Considered Options

- **把锚定写进材料 `invMass`**（离散化时就置零）。否掉：那个零从此有两个含义，`pick.js` 与
  `grip.js` 当场变成假话，而[01](../../.scratch/proxy-geometry/issues/01-boundary-condition-vocabulary.md)
  诊断的「三种含义纠缠」这才**第一次真的发生**——今天并没有发生。
- **塞进现有的 `prescribed` 集合**。否掉：那个集合的契约是「一次一个 driver，`setPrescribed`
  直接替换上一批」，第一次抓握就会把锚定擦掉；要救它就得给集合加生命周期语义，等于把
  [ADR-0002](0002-prescribed-degrees-of-freedom.md) 按归属分开的两件事又焊回去。

## Consequences

- **「共用一个编码」不是纠缠的根因**，把**不同归属**的东西写进**同一个数组**才是。Vellum 的
  Permanent / Stopped 共用 pin 机制却不共用编码，是同一个判断的判例。
- **落点的机制不在这条 ADR 的射程内**（改哪个文件、缝架在哪、第二个集合长什么样），那是锚定机制
  那张图的事。这里定的是机制必须满足的**语义约束**。
- **修正接口草案 03 的 I1**：I1 写成「`invMass[i] === 0` 表示该槽位此刻不被解算，可能是惰性、
  也可能是被规定」，但它挂在接口条目 1 的 `dof.invMass` 上——那是**代理几何交出来的**，它不可能
  知道谁被规定了。I1 要收窄成：`dof.invMass` 的零**只**表示惰性；「此刻不被解算」是 `Particles`
  合成之后才成立的读法，不是代理几何的接口承诺。
- **惰性节点不入 `CONTEXT.md`**。共识词是 `inactive node`（MPM），但两边文献都把它归为离散化产物
  与要被消灭的开销，从不归进边界条件一族。它是 `ARCHITECTURE.md` 4.2 的后果，不是领域概念。仓库
  自造的 `inert` 改名为 `inactive`，改动随离散化词表那一趟落盘。
